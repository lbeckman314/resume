To Whom it May Concern,

\vspace*{\baselineskip}

As a Research Software Engineer at OHSU's Knight Cancer Institute, I lead development of orchestration systems that run autonomous workloads across cloud and HPC environments, and I've spent the past two years building hands-on fluency with LLM tooling and agentic workflows on top of that foundation. I'd welcome the chance to bring both --- distributed systems architecture and practical AI-assisted engineering --- to Mozilla's new agentic browser infrastructure team.

\paragraph{EXPERIENCE}\

\vspace*{\baselineskip}

My background spans the two things this role asks someone to bridge: systems architecture and applied AI tooling.

\begin{itemize}

\item Lead developer of \link{https://github.com/ohsu-comp-bio/funnel}{Funnel}, a workflow orchestration toolkit that executes tasks across cloud and HPC backends through a standard task-execution API --- the kind of orchestration-layer design this role calls for, applied to genomic pipelines instead of AI agents.

\item Built a Nextflow plugin and Python client library around the GA4GH Task Execution API, giving existing pipelines a common interface to run against multiple execution backends without rewriting pipeline code --- direct experience designing clean API boundaries so early architectural choices don't block future scale.

\item Evaluate and run quantized open-weight models (Gemma, Qwen) locally via Ollama for agentic task prototyping, and use Claude Code and OpenCode daily to design repeatable multi-step automation workflows --- practical, everyday experience with the AI-native tooling this role treats as core to how the team ships.

\item Lead developer of the \link{https://fhir-aggregator.org/}{FHIR-Aggregator} client, built on HL7 FHIR for the NIH Cloud Platform Interoperability program, integrating with Google's Cloud Healthcare API to unify clinical and genomic data under a standard schema --- experience shipping a complex system from a blank slate, alone, end to end.

\item Coordinated task dependencies and delivery milestones with external \link{https://www.ga4gh.org/}{GA4GH} consortium partners across institutions, and regularly translate technical systems into plain language for non-technical stakeholders and research collaborators.

\end{itemize}

\paragraph{WHY THIS ROLE}\

\vspace*{\baselineskip}

I'll be candid about fit: my hands-on agentic-systems experience is real but newer than a Staff-level posting typically implies, and it comes from a research lab rather than a startup. What I bring instead is the pattern underneath the role --- I've spent my career building the orchestration layers that let autonomous workloads run reliably across heterogeneous backends, and I've spent the last two years pointing that same instinct at LLM-driven tooling, evaluating models, and prototyping agent workflows because I find the problem genuinely compelling, not because a project required it.

\vspace*{\baselineskip}

Mozilla's mission --- an internet built for people, not just companies --- is also why this posting stood out to me specifically. I'd rather help build the infrastructure for agentic browsing at an organization whose incentives are aligned with users than at one where they aren't.

\vspace*{\baselineskip}

I would welcome the opportunity to discuss whether my background is the right fit for where this team is headed. Please see my attached resume for further detail.
